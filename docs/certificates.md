# Sprint 6 — Сертификаты

## Жизненный цикл

Сертификат выдаётся на одну запись `Enrollment` только если текущий расчёт
`ProgressService.reconcile()` подтверждает 100%: завершены все учитываемые
уроки и все опубликованные обязательные проверки. Обязательный тест засчитывает
успешная попытка, практическое задание — принятое преподавателем решение.
Необязательные и архивированные проверки не блокируют выдачу, поскольку
исключаются из общего прогресса Sprint 5.

`POST /api/v1/certificates/issue` принимает `{ "enrollment_id": "<uuid>" }`.
Backend проверяет право `certificates:issue_self`, владельца записи и актуальный
прогресс. Неполный курс возвращает `409 course_not_completed` с текущими
счётчиками. Повторный запрос для уже сертифицированной записи возвращает тот же
сертификат. В `certificates.enrollment_id` установлено уникальное ограничение;
перед проверкой прогресса backend блокирует строку enrollment через
`SELECT ... FOR UPDATE`. Совместно это сериализует запросы и не допускает
дубликатов даже после отмены и реактивации записи.

## Snapshot и модель данных

`Certificate` содержит UUID, уникальный FK `enrollment_id` с `ON DELETE
RESTRICT`, имя получателя и название курса в snapshot, дату завершения и дату
выдачи, уникальные номер сертификата и verification code, версию шаблона,
закрытый storage key и `created_at`. Изменение профиля и курса не меняет
выданный документ. Отдельные копии user/course FK не нужны: enrollment
сохраняется ограничением `RESTRICT` и связывает запись с владельцем.

## PDF и хранилище

ReportLab формирует одностраничный A4 PDF в альбомной ориентации в момент
выдачи. Шаблон версии `1` использует включённые в репозиторий Noto Sans Regular
и Bold для кириллицы; лицензия шрифта находится рядом с файлами в
`backend/app/modules/certificates/assets/OFL.txt`. PDF строится исключительно
из snapshot и включает номер, даты и ссылку проверки.

Файл записывается атомарно через временный файл в приватную директорию,
настраиваемую `CERTIFICATES_STORAGE_DIR` (по умолчанию
`backend/var/certificates`). Публичная статика директорию не обслуживает.
В БД хранится только случайный ключ-файл; API его не раскрывает. Ошибка
фиксации БД приводит к удалению созданного PDF; отсутствующий PDF даёт
`404 certificate_file_missing`.

`PUBLIC_FRONTEND_URL` задаёт базовый адрес публичной страницы проверки,
например `http://127.0.0.1:5173`.

## API и доступ

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `POST /api/v1/certificates/issue` | `certificates:issue_self` | Выдать или вернуть сертификат текущей записи |
| `GET /api/v1/certificates/me` | `certificates:read_self` | Список сертификатов пользователя |
| `GET /api/v1/certificates/{id}/download` | `certificates:read_self` + владелец | Приватный `application/pdf`, `no-store` |
| `GET /api/v1/certificates/verify/{code}` | Публичный | Валидность, имя, курс, номер и дата выдачи |

Публичный endpoint возвращает `404 certificate_not_found` для неизвестного кода.
Он не раскрывает email, UUID, enrollment ID, историю, storage key или путь к
файлу. Код создаётся `secrets.token_urlsafe(32)` и имеет уникальное ограничение.
Self-разрешения добавлены ролям пользователей кроме `guest`; публичная
проверка авторизационного разрешения не требует.

## Frontend

- `/certificates` — список, ссылки на проверку и авторизованное скачивание;
- `/certificates/verify/:verificationCode` — публичное подтверждение;
- завершённая активная запись в «Моём обучении» показывает действие запроса;
- пустое состояние объясняет условия получения сертификата.

Светлая/тёмная тема переключается кнопкой в общей шапке. Первый визит
использует `prefers-color-scheme`; затем выбранное значение хранится в
`localStorage` и синхронизируется между вкладками. Тема применяется до старта
React, чтобы не показывать вспышку другой палитры.

## Миграция и проверки

`0008_certificates` создаёт таблицу, ограничения и индекс `issued_at`, а также
разрешения RBAC для всех обычных ролей. Для проверки downgrade используется
отдельная PostgreSQL база тестов; рабочая база мигрируется только вперёд.
